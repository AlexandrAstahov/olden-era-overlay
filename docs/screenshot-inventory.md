# Screenshot Inventory

## Назначение

Этот файл нужен для учёта скриншотов, которые используются для:
- ручного анализа интерфейса;
- подготовки OCR-пайплайна;
- подготовки шаблонов для OpenCV;
- тестирования decision engine на реальных игровых экранах.

## Правила хранения

- Массовые личные или сырые скриншоты можно хранить локально в `assets/screenshots/raw/`
- Размеченные версии можно хранить в `assets/screenshots/labeled/`
- Эталонный набор для репозитория хранится в `assets/screenshots/sample/`
- Один скриншот = одна строка в таблице ниже
- Значения, которые не подтверждены визуальной проверкой, помечаются как `нужно уточнить`

## Формат именования

Текущее именование в sample-наборе основано на типе экрана и, местами, на уровне выбора.

Примеры:
- `hero-pick.png`
- `skill-pick_2lv.png`
- `sub-skill-pick_4lv.png`
- `final-build.png`

## Что нужно уточнить вручную

Для каждого скриншота позже нужно вручную дописать:
- имя героя;
- класс героя;
- какие навыки уже взяты;
- какие 3 опции показаны;
- есть ли читаемый текст для OCR;
- общее качество скрина (`good`, `medium`, `bad`).

## Следующий шаг

После этого файла нужно:
1. выбрать 3–4 лучших скриншота из `skill-pick_*`;
2. создать стартовые `data/skills.json`, `data/heroes.json`, `data/rules.json`;
3. подготовить документ decision model;
4. только потом переходить к первому Python-прототипу анализа одного изображения.
