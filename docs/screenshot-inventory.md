# Screenshot Inventory

## Назначение

Этот файл нужен для учёта скриншотов, которые будут использоваться для:
- ручного анализа интерфейса;
- проверки OCR;
- подготовки шаблонов для OpenCV;
- тестирования decision engine на реальных данных.

## Правила хранения

- Оригинальные скриншоты складывать в `assets/screenshots/raw/`
- Если скриншот был переименован, обрезан или размечен — сохранять копию в `assets/screenshots/labeled/`
- Имена файлов делать понятными и последовательными
- Желательно сохранять PNG
- Один скриншот = одна строка в таблице ниже

## Формат именования

Рекомендуемый шаблон:

`YYYY-MM-DD_screen-type_short-description_01.png`

Примеры:
- `2026-06-05_skill-pick_knight-offense_01.png`
- `2026-06-05_hero-pick_start-choice_01.png`
- `2026-06-05_final-build_necromancer_01.png`

## Инвентарь

| Файл | Тип экрана | Герой / класс | Что видно на скрине | Качество | Комментарий |
|------|------------|---------------|---------------------|----------|-------------|
| example.png | skill-pick | неизвестно | 3 навыка, верхняя панель навыков | good | пример строки, удалить позже |

## Типы экранов

Использовать такие значения:
- `hero-pick`
- `skill-pick`
- `final-build`
- `unknown`

## Оценка качества

Использовать такие значения:
- `good` — текст и иконки хорошо читаются
- `medium` — читаемо, но есть шум или лёгкое размытие
- `bad` — плохо подходит для OCR/CV

## Что нужно собрать сначала

Минимальный стартовый набор:
- 5–10 скриншотов `skill-pick`
- 2–3 скриншота `hero-pick`
- 2–3 скриншота `final-build`

## Следующий шаг

После заполнения этого файла:
1. выберем 3 лучших скриншота для первого прототипа;
2. начнём делать JSON-базу;
3. затем перейдём к анализу одного изображения.
