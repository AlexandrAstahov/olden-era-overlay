# План разработки

Пошаговый план без перескакивания этапов. Каждый этап завершается проверяемым артефактом и коммитом в Git.

---

## Этап 0. Стартовый workspace ✅

**Цель:** каркас репозитория без кода логики.

**Результат:**

- Структура каталогов
- Документация в `docs/`
- Пустые JSON в `data/`
- `README.md`, `.gitignore`
- `git init` и первый коммит

**Проверка:** дерево папок совпадает со спецификацией; все markdown и JSON открываются без ошибок.

---

## Этап 1. Окружение Python

**Цель:** воспроизводимое локальное окружение на Windows.

**Действия:**

1. Установить Python 3.11+ (официальный installer с python.org).
2. В корне проекта: `python -m venv .venv`
3. Активировать: `.venv\Scripts\activate`
4. Создать `requirements.txt` с минимальным набором (пока можно пустой или с комментариями).
5. Зафиксировать версию Python в `docs/dev-plan.md` или отдельной заметке.

**Результат:** виртуальное окружение, понятная инструкция в README (позже).

**Коммит:** `chore: add Python venv and requirements stub`

---

## Этап 2. Инвентарь скриншотов

**Цель:** собрать и каталогизировать референсные изображения арены.

**Действия:**

1. Сделать скриншоты экранов выбора в игре (Win+Shift+S или встроенный захват).
2. Сохранить в `assets/screenshots/raw/` с понятными именами: `arena_skill_pick_001.png`.
3. Заполнить таблицы в `docs/screenshot-inventory.md`.
4. Выбрать **один** экран для MVP (отметить в inventory).

**Результат:** ≥ 5 скриншотов одного типа экрана + заполненный inventory.

**Коммит:** `docs: add arena screenshot inventory` (raw-файлы — по желанию, крупные можно не коммитить; см. `.gitignore`).

---

## Этап 3. Схема и старт базы знаний

**Цель:** описать и частично заполнить JSON без выдуманных игровых статов.

**Действия:**

1. Уточнить схему в `docs/knowledge-model.md` по реальным скринам.
2. Добавить в `data/skills.json` только те навыки, которые видны на скриншотах (id, отображаемое имя, источник).
3. Заготовить `data/rules.json` с 2–3 простыми правилами приоритета для MVP-экрана.
4. `data/heroes.json` — по мере появления данных с экрана героя.

**Результат:** валидный JSON, согласованный с inventory.

**Коммит:** `data: initial knowledge base schema and entries`

---

## Этап 4. Прототип детекции на скриншотах

**Цель:** определить тип экрана и области интереса (ROI) без live capture.

**Действия:**

1. Модуль `src/detection/` — загрузка изображения, обрезка ROI (координаты из inventory).
2. Модуль `src/parsing/` — OCR (PaddleOCR) или matchTemplate (OpenCV) для иконок.
3. Скрипт в `scripts/analyze_screenshot.py` — вход: путь к PNG, выход: JSON с вариантами.
4. Прогон по всем скринам из этапа 2.

**Результат:** скрипт печатает распознанные варианты; ручная сверка с inventory.

**Коммит:** `feat: screenshot detection prototype`

---

## Этап 5. Decision engine

**Цель:** по списку вариантов и контексту вернуть рекомендацию.

**Действия:**

1. `src/knowledge/` — загрузка JSON, поиск сущностей по id/имени.
2. `src/decision/` — применение правил из `rules.json` (приоритеты, теги, исключения).
3. Юнит-тесты в `tests/` на фиксированных входах (без OCR).

**Результат:** функция `recommend(options, context) -> Recommendation`.

**Коммит:** `feat: decision engine with rules`

---

## Этап 6. Overlay MVP

**Цель:** показать подсказку поверх рабочего стола / окна игры.

**Действия:**

1. `src/overlay/` — прозрачное окно PySide6, текст рекомендации.
2. `src/app/` — минимальный entry point: загрузка скриншота → detect → decide → show overlay (для отладки).
3. Проверить: overlay не перехватывает клики (click-through).

**Результат:** при запуске на тестовом скрине видна подсказка.

**Коммит:** `feat: overlay window MVP`

---

## Этап 7. Live capture

**Цель:** заменить файл скриншота захватом экрана в цикле.

**Действия:**

1. `src/capture/` — захват области экрана или окна игры (mss / WinAPI).
2. Троттлинг (например 1–2 FPS достаточно для экрана выбора).
3. Стабилизация: не дергать OCR, пока кадр не изменился.

**Результат:** overlay обновляется при смене экрана в игре.

**Коммит:** `feat: live screen capture`

---

## Этап 8. Тесты и стабилизация MVP

**Цель:** регрессия и документация для пользователя.

**Действия:**

1. Набор эталонных скринов в `tests/fixtures/`.
2. Тесты: detection snapshot, decision rules.
3. Обновить README: установка, запуск, ограничения.
4. Чеклист ручного теста в `docs/` или README.

**Результат:** воспроизводимый MVP, готовый к расширению на другие экраны арены.

**Коммит:** `test: regression suite and user docs`
