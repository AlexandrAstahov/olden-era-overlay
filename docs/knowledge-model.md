# Модель базы знаний

Локальные данные хранятся в `data/*.json`. Формат эволюционирует по мере сбора реальных скриншотов; **не заполнять выдуманными игровыми статами**.

## Общие принципы

- Каждая сущность имеет стабильный `id` (латиница, snake_case).
- Отображаемые имена (`name`) — как на экране игры (может быть кириллица).
- Поле `source` фиксирует происхождение записи: `screenshot`, `manual`, `wiki` и т.д.
- Версия схемы: `schema_version` в корне каждого файла (когда появятся записи).

## Файл `data/skills.json`

Навыки, перки и схожие бонусы, встречающиеся на экранах выбора арены.

### Планируемая структура

```json
{
  "schema_version": 1,
  "skills": [
    {
      "id": "skill_example",
      "name": "Отображаемое имя с экрана",
      "aliases": [],
      "category": "skill",
      "tags": [],
      "icon_template": "assets/templates/skills/skill_example.png",
      "notes": "",
      "source": "screenshot",
      "verified": false
    }
  ]
}
```

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Уникальный идентификатор |
| `name` | string | Текст с UI игры |
| `aliases` | string[] | Альтернативные написания для OCR |
| `category` | string | `skill`, `perk`, `spell`, … — уточняется по UI |
| `tags` | string[] | Для правил: `damage`, `economy`, `defense`, … |
| `icon_template` | string | Путь к шаблону иконки (опционально) |
| `notes` | string | Комментарий разработчика |
| `source` | string | Откуда взята запись |
| `verified` | bool | Подтверждено вручную |

**Текущее состояние:** пустой объект `{}` — схема зафиксирована в этом документе, записи добавляются на этапе 3.

## Файл `data/heroes.json`

Герои и связанные с ними данные для контекста решений (если видны на экране).

### Планируемая структура

```json
{
  "schema_version": 1,
  "heroes": [
    {
      "id": "hero_example",
      "name": "Имя героя",
      "faction": "",
      "tags": [],
      "notes": "",
      "source": "screenshot",
      "verified": false
    }
  ]
}
```

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Уникальный идентификатор |
| `name` | string | Имя на экране |
| `faction` | string | Фракция, если распознаётся |
| `tags` | string[] | Теги для правил |
| `notes` | string | Комментарий |
| `source` | string | Источник |
| `verified` | bool | Подтверждено вручную |

**Текущее состояние:** пустой объект `{}`.

## Файл `data/rules.json`

Правила приоритета для decision engine. Не дублирует игровую математику — только **политика выбора** для помощника.

### Планируемая структура

```json
{
  "schema_version": 1,
  "default_strategy": "priority_list",
  "screens": {
    "arena_skill_pick": {
      "description": "Экран выбора навыка в арене",
      "match_tags": ["arena", "skill_pick"],
      "rules": [
        {
          "id": "prefer_tag_damage",
          "type": "prefer_tag",
          "tag": "damage",
          "weight": 10,
          "enabled": true
        }
      ]
    }
  }
}
```

### Типы правил (расширяемый список)

| type | Назначение |
|------|------------|
| `prefer_tag` | Повысить варианты с указанным тегом |
| `deprioritize_tag` | Понизить варианты с тегом |
| `prefer_id` | Явный приоритет конкретного `id` |
| `exclude_id` | Исключить вариант из рекомендаций |

**Текущее состояние:** пустой объект `{}` — правила добавляются после выбора MVP-экрана.

## Чеклист перед добавлением записи

- [ ] Есть скриншот в `assets/screenshots/` или запись в `screenshot-inventory.md`
- [ ] `name` совпадает с тем, что видно на экране
- [ ] `id` уникален в файле
- [ ] `source` и `verified` заполнены честно
- [ ] JSON валиден (проверка: `python -m json.tool data/skills.json`)
