# Продуктовое описание

## Название

**Heroes of Might and Magic: Olden Era Arena Overlay Helper**

## Проблема

В режиме Арена игроку часто нужно быстро выбрать один из нескольких вариантов (навык, перк, герой и т.д.). Оценка «лучшего» выбора зависит от текущей сборки, уже взятых бонусов и правил режима. Удерживать всё в голове сложно, особенно под давлением таймера или в длинной сессии.

## Решение

Локальное приложение для Windows, которое:

1. Захватывает или получает изображение экрана игры в режиме Арена.
2. Определяет тип текущего экрана выбора и извлекает доступные варианты.
3. Сопоставляет варианты с локальной базой знаний.
4. Применяет правила приоритета и показывает **визуальную подсказку** поверх интерфейса игры.

Пользователь сам кликает в игре — приложение только подсказывает.

## Целевой пользователь

Игрок HoMM: Olden Era, регулярно играющий в режим Арена и желающий снизить количество ошибочных выборов без читов и автоматизации.

## Сценарии использования

### Сценарий 1: Выбор навыка

1. В арене появляется экран с несколькими навыками на выбор.
2. Overlay-помощник распознаёт варианты и текущий контекст (герой, уже взятые навыки — по мере реализации).
3. На overlay отображается рекомендуемый навык и краткое обоснование.

### Сценарий 2: Выбор перка / бонуса

1. Игрок видит экран выбора перков или аналогичного бонуса.
2. Приложение сопоставляет варианты с `data/skills.json` / `data/rules.json`.
3. Подсказка указывает приоритетный вариант.

### Сценарий 3: Отладка на скриншотах (этап разработки)

1. Разработчик кладёт скриншот в `assets/screenshots/raw/`.
2. Запускает скрипт анализа (будущий этап).
3. Сверяет распознанные варианты с `docs/screenshot-inventory.md` и дорабатывает шаблоны/OCR.

## Ограничения и принципы

| Разрешено | Запрещено |
|-----------|-----------|
| Захват экрана (BitBlt, DXGI и т.п.) | Автоклик |
| OCR и сопоставление шаблонов | Управление мышью/клавиатурой |
| Прозрачный overlay поверх окна | Чтение/запись памяти процесса игры |
| Локальные JSON-данные | Инъекции DLL / хуки в процесс игры |
| Ручная настройка областей экрана | Обязательные внешние API |

## Scope MVP

Минимально жизнеспособная версия должна:

- [ ] Работать на Windows 10/11.
- [ ] Распознавать **один** тип экрана выбора в арене (конкретный экран уточняется при сборе скриншотов).
- [ ] Извлекать список вариантов с экрана (OCR +/или шаблоны иконок).
- [ ] Сопоставлять варианты с локальной базой знаний.
- [ ] Показывать overlay с одной рекомендацией (название + краткий приоритет).
- [ ] Работать сначала на **статичных скриншотах**, затем на live capture.

**Вне scope MVP:**

- Полное покрытие всех экранов арены.
- Автоматическое обучение моделей на больших датасетах.
- Мультиплеер, облако, аккаунты.
- Управление игрой от имени пользователя.

## Критерии успеха MVP

1. На тестовом наборе из N скриншотов (N ≥ 10) приложение верно определяет тип экрана и список вариантов в ≥ 80% случаев.
2. Рекомендация совпадает с заранее описанными правилами в `data/rules.json` для тех же сценариев.
3. Overlay виден поверх окна игры и не блокирует клики пользователя (click-through или компактная зона).
4. Нет вмешательства в процесс игры — проверяется ревью кода и поведением.

## Риски

| Риск | Митигация |
|------|-----------|
| Смена UI игры в патче | Версионирование шаблонов, инвентарь скриншотов по версии игры |
| Ошибки OCR на мелком тексте | Шаблоны иконок, предобработка OpenCV |
| Разные разрешения / масштаб | Нормализация координат, тест на 1080p и 1440p |
| Неточные игровые данные | Не выдумывать статы; заполнять базу из скринов и проверяемых источников |

## Открытые вопросы

- Какой именно экран выбора берём первым для MVP? → решить после первой партии скриншотов.
- Фиксированное разрешение игры или поддержка нескольких? → зафиксировать в `screenshot-inventory.md`.
- Нужна ли привязка overlay к окну игры или достаточно полноэкранного overlay? → этап overlay MVP.
